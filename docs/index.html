🔍 Flaky Scout

CI test-failure triage that never phones home.

When a test fails, Flaky Scout figures out why — selector drift, a real assertion failure, flaky timing, or the environment being down — using instant pattern matching first, and your own local AI model only when it has to. Your logs never leave the machine they ran on.

How it classifies a failure

Cheapest check first — the AI model is a last resort, not the default.

  1. 1

    Signature match (instant, free)

    Regex patterns for the common, well-known failure shapes — NoSuchElementException, TimeoutException, ConnectionRefusedError, assertion failures, and more. Most failures stop here.

  2. 2

    Knowledge-base cache (instant, free)

    A novel failure the AI has classified before gets cached, keyed by a normalized hash of the log — so line numbers and timestamps don't matter. Seen it once, it's instant from then on.

  3. 3

    Local model (a few seconds)

    Only genuinely new patterns reach your own model via Ollama — nothing is sent to a third-party API. It returns a category, root cause, fix hint, and whether it's safe to auto-retry.

Quick start

Needs a self-hosted CI runner with Ollama installed (ollama pull qwen3:8b) — that's the trade-off for nothing leaving the box. 

# .github/workflows/test.yml
jobs:
  test:
    runs-on: self-hosted
    steps:
      - uses: actions/checkout@v4
      - run: pytest --junitxml=report.xml
        continue-on-error: true
      - uses: Sandy-262/flaky-scout@v1
        with:
          junit-xml: report.xml
          post-comment: true
          github-token: ${{ secrets.GITHUB_TOKEN }}

Works with any test runner that emits JUnit XML — pytest, Jest (jest-junit), TestNG/Selenium, Appium suites, and more. Full setup and the CLI usage are in the README.
