WHY IT MATTERS

The business case, in plain English.

Not another dashboard. Not another cloud subscription. A quiet fix for a problem that's quietly costing you engineering hours every single week.

Nothing to explain to Security

Test logs can contain real customer data, internal URLs, API payloads. Flaky Scout's AI runs on hardware you own — nothing is ever transmitted to a third party. No vendor data-sharing agreement to negotiate.

Costs the same at 10 or 10,000 runs

Cloud "AI DevOps" tools bill per API call — the cost scales with your team's activity. Flaky Scout runs on a model you already host. Ten triages or ten thousand, the bill is the same: zero.

Gives engineers their time back

Someone currently reads every red build and decides "real bug or noise?" by hand. Flaky Scout makes that call instantly, so your team spends time fixing things, not diagnosing them.

No rip-and-replace

Works with whatever your teams already use — pytest, Jest, Selenium, Appium, TestNG. If it can produce a standard test report, Flaky Scout can read it. Nothing to migrate.

HOW IT WORKS

Smart enough to know when not to think too hard.

Most failures are old, familiar problems. Flaky Scout recognizes those instantly and only wakes up its AI brain for the genuinely new ones — so it's fast, cheap, and never wasteful.

  1. 1

    Instant recognition (milliseconds, free)

    Flaky Scout already knows the usual suspects — a missing button, a slow page, a broken connection. It spots these the moment the failure comes in, no AI required.

  2. 2

    Memory (milliseconds, free)

    Seen something like this before? It remembers — even if the details changed slightly — and answers instantly instead of asking the AI to figure it out twice.

  3. 3

    Your own private AI (a few seconds)

    Only a genuinely new kind of failure reaches the AI model — running on your own hardware via Ollama, never a third-party cloud. It explains what broke, why, and whether it's safe to just try again.

FOR YOUR ENGINEERING TEAM

Quick start

Needs a self-hosted CI runner with Ollama installed (ollama pull qwen3:8b) — that one requirement is the entire trade-off for "nothing ever leaves the box." 

# .github/workflows/test.yml
permissions:
  contents: read
  pull-requests: write
jobs:
  test:
    runs-on: self-hosted
    steps:
      - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0
      - run: pytest --junitxml=report.xml
        continue-on-error: true
      - uses: Sandy-262/flaky-scout@7456a8e226a738c86b8ea805fb1ac6eaed27be01 # v1.0.0
        with:
          junit-xml: report.xml
          post-comment: true
          github-token: ${{ secrets.GITHUB_TOKEN }}

Works with any test runner that emits JUnit XML — pytest, Jest (jest-junit), TestNG/Selenium, Appium suites, and more. Security details (and why the Action references are pinned to commit hashes, not version tags) are in SECURITY.md. Full setup and the CLI usage are in the README.
